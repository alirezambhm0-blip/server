# ممیزی همگام‌سازی (Sync Audit) — قبل از هر تغییری

## این بسته چیست؟
طبق اصول «تحلیل → تعیین دامنه → کوچک‌ترین تغییر»، قبل از اینکه حتی یک فایل روی سیستم تو بازنویسی شود، ابتدا مشخص می‌کنیم **دقیقاً کدام فایل‌ها** با نسخه تأییدشده فرق دارند. این ابزار **فقط‌خواندنی** است و هیچ فایلی را تغییر نمی‌دهد.

## فایل‌ها
- `verified-manifest.txt` — هش ۲۳۳ فایل تأییدشده (سورس/کانفیگ/اسکریپت هر دو پروژه، بدون .env)
- `sync-audit.ps1` — اسکریپت مقایسه (PowerShell)
- `run-audit.cmd` — اجراکننده ساده (دابل‌کلیک)
- این راهنما

## مراحل
1. این ۴ فایل را **در روت پروژه** استخراج کن:
   `C:\Users\sam\Desktop\workspace-01`
2. روی `run-audit.cmd` دابل‌کلیک کن (یا در CMD: `run-audit.cmd`)
3. فایل `sync-audit-report.txt` ساخته می‌شود — **محتوایش را برایم بفرست** (یا حداقل ۴ عدد MATCH/DIFFER/MISSING/EXTRA و لیست DIFFER و MISSING)

## خروجی چه معنای دارد؟
| وضعیت | معنی | اقدام بعدی |
|---|---|---|
| MATCH | فایل دقیقاً مثل نسخه تأییدشده | هیچ‌کدام — دست نمی‌خورد ✅ |
| DIFFER | فایل محلی با نسخه تأییدشده فرق دارد | برای هرکدام جداگانه با توجیه تصمیم می‌گیریم |
| MISSING | فایلی که باید باشد و نیست | فقط همان‌ها اضافه می‌شوند |
| EXTRA | فایل فقط روی سیستم توست | گزارش می‌شود؛ **بدون اجازه تو دست نمی‌خورد** |

## بعد از گزارش
بر اساس گزارش، بسته **`sync-minimal.zip`** می‌سازم که فقط شامل فایل‌های DIFFER/MISSING است — هر کدام با دلیل مشخص. همه فایل‌های MATCH و EXTRA کاملاً دست‌نخورده می‌مانند. این دقیقاً همان «کوچک‌ترین تغییر امن» است.

## نسخه ۱.۱ — اصلاحیه
رفع باگ: فایل‌هایی که در مسیرشان کروشه `[ ]` دارند (مثل `orders/[id].tsx`) به‌اشتباه MISSING گزارش می‌شدند، چون PowerShell الگوی wildcard را روی مسیر اعمال می‌کرد. حالا مقایسه با `-LiteralPath` انجام می‌شود.
