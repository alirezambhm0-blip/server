## ۱) مفهوم: آپدیت هوایی یعنی چی؟ (با یک مثال ساده)

اپلیکیشن را یک **رستوران** در نظر بگیر:
- ساختمان رستوران = نسخه‌ای که روی گوشی نصب می‌شود (فایل APK). برای تغییر ساختمان باید دوباره ساخت و دوباره در بازار منتشر کرد. 🔨
- **منوی رستوران** = متن‌ها، رنگ‌ها، ظاهر کارت‌ها، صفحه‌بندی‌ها، رفع باگ‌های نمایشی. 🍽

**آپدیت هوایی = تعویض منو بدون تخریب ساختمان.**
یعنی تو یک دستور می‌زنی و هر گوشی‌ای که اپ را نصب دارد، دفعه بعد که اپش را باز کند، **منوی جدید** را می‌بیند — بدون دانلود از بازار، بدون اینکه کاربر کاری کند.

### چه چیزهایی هوایی عوض می‌شود؟
| ✅ با یک دستور هوایی می‌رسد | ❌ نیاز به ساخت و انتشار مجدد (بازار) دارد |
|---|---|
| متن‌ها و جمله‌های فارسی | افزودن/حذف پکیج نیتیو (مثل پکیج دوربین جدید) |
| ظاهر کارت محصول، رنگ، چیدمان | تغییر آیکن اپ، نام اپ، اسپلش |
| رفع باگ‌های منطقی/نمایشی JS | افزودن دسترسی جدید اندروید (Permission) |
| تغییر در صفحات و فلوها | ارتقای نسخه Expo SDK |

> قانون طلایی: **هر وقت فقط فایل‌های JS/TSX عوض شده‌اند → هوایی می‌رسد.** وگرنه باید باز هم Build.

## ۳) راه‌اندازی یک‌بار — قدم‌به‌قدم

> ⚠️ **قبل از شروع، این دو فایل را از زیپ ۶-۴ جایگزین کرده باش:** `eas.json` و `package.json` (در پوشه wholesale-mobile). داخلشان چه اضافه شده؟ (بدان تا راحت باشی):
> - در `eas.json` به دو پروفایل `preview` و `production` فیلد `channel` اضافه شده — «کانال» همان خیابانی است که آپدیت‌ها از آن به گوشی‌ها می‌رسند؛ هر نسخه نصبی به کانال خودش گوش می‌دهد.
> - در `package.json` دو دستور کوتاه `update` و `update:preview` — تا مجبور نباشی دستور بلند حفظ کنی.

### قدم ۰ — ساخت حساب رایگان Expo (۵ دقیقه)
1. برو به سایت **expo.dev** و **Sign Up** کن (ایمیل + رمز عبور). ورود را یادت باشد.
2. (اگر اتصال اینترنتت هنگام کار با سرویس‌های expo ناپایدار بود، با اتصال پایدارتری امتحان کن — بعضی سرویس‌های بین‌المللی با IPهای محلی نوسان دارند.)

### قدم ۱ — نصب ابزار و ورود در سیستم (یک‌بار)
یک پنجره **CMD جدید** باز کن و برو به پوشه موبایل:
```bat
cd C:\Users\sam\Desktop\workspace-01\wholesale-mobile
npm install -g eas-cli
eas login
```
- با `npm install -g eas-cli` ابزار Expo **یک‌بار برای همیشه** روی سیستم نصب می‌شود (`-g` یعنی نصب سراسری — نام واقعی بسته `eas-cli` است؛ نوشتن `npx eas` درست نیست چون npm دنبال بسته‌ای به اسم `eas` می‌گردد و خطا می‌دهد). متن‌های زرد `npm warn` طبیعی‌اند.
- سپس `eas login`: ایمیل و رمز عبور همان حساب Expo را بده. **موقع تایپ رمز روی صفحه چیزی دیده نمی‌شود** (حتی ستاره نه) — طبیعی است؛ تایپ کن و Enter بزن. اگر نوشت `Logged in` ✅ برو سراغ قدم بعد.

### قدم ۲ — معرفی پروژه به حسابت (یک‌بار)
همان‌جا:
```bat
eas init
```
- اگر پرسید پروژه ساخته شود؟ `Y` بزن.
- حالا فایل `app.json` را باز کن (Notepad): در انتهای آن یک بخش جدید `extra → eas → projectId` دیده می‌شود — یک کد طولانی مثل `a1b2c3...`. این «شناسه پروژه» توست. ✅

### قدم ۳ — اتصال آدرس آپدیت به شناسه پروژه (یک‌بار)
```bat
eas update:configure
```
- دوباره `app.json` را باز کن: در بخش `updates` آدرس قبلی از حالت `.../<REPLACE_ME_PROJECT_ID>` به `https://u.expo.dev/<شناسه واقعی تو>` تغییر کرده است. ✅
- (این دقیقاً همان تکه‌ای بود که گفتم «باید با کلید حساب تو نوشته شود، نه با دست من» — تو نوشتیش! ✍️)

### قدم ۴ — ساخت اولین نسخه نصبی برای تست (۱۵-۲۵ دقیقه — صبر ☕)
```bat
eas build --profile preview --platform android
```
- نیازی به اکانت گوگل‌پلی نیست؛ خروجی یک **APK تستی** است.
- در پایان یک **لینک/QR‌کد** می‌دهد. با گوشی بازش کن، فایل را دانلود و نصب کن (شاید گوشی اجازه «نصب از منابع ناشناس» بخواهد — موقتاً روشن کن).
- *توضیح:* این بیلد به «کانال preview» که در eas.json ساختیم گوش می‌دهد. نسخه نهایی بازار هم پروفایل `production` و کانال `production` را دارد — اول همیشه روی preview تست می‌کنیم، بعد production.

### قدم ۵ — تست طلایی: اولین آپدیت هوایی 🎯
1. یک تغییر خیلی کوچک و قابل‌دیدن در اپ بده — برای اولین تست، فقط یک متن را عوض کن (بهتر است با من هماهنگ کنی، من یک تغییر امن پیشنهاد می‌دهم یا خودم در یک زیپ می‌فرستم).
2. حالا:
```bat
npm run update:preview -- "اولین آپدیت هوایی من"
```
3. در خروجی چند ثانیه بعد پیام موفقیت می‌آید (Update published ✔).
4. روی گوشی: اپ preview را **کاملاً ببند** (از لیست برنامه‌ها swipe کن بیرون) و دوباره باز کن. تغییر را باید ببینی! (اگر ندیدی، یک‌بار دیگر ببند/باز کن — گوشی موقع شروع، آپدیت را چک و بعداً اعمال می‌کند.)
🎉 اگر تغییر را دیدی، کل سیستم OTA زنده است!

## ۵) روال روزانه تو بعد از این

### سناریوی «رفع باگ ظاهری برای همه کاربرها»
1. تغییری که می‌خواهی (با من یا خودت) اعمال می‌شود.
2. `npm test`؟ نه لازم نیست — آن برای بک‌اند بود. اینجا: `npm run web` و یک نگاه سریع که همه‌چیز سالم است.
3. یک دستور:
```bat
npm run update -- "متن کوتاه این آپدیت"
```
4. تمام. تا دقایقی دیگر گوشی‌ها موقع باز شدن بعدی اپ، آپدیت را می‌گیرند.

### سناریوی «می‌خواهم اول روی پیش‌نمایش تست کنم»
همان، فقط با `npm run update:preview -- "..."` و تست روی APK preview خودت.

## ۷) نکات مهم که باید بدانی (یک‌بار بخوان، همیشه یادش کن)
1. **پلن رایگان** Expo ماهانه برای ۱۰۰۰ کاربر فعال (MAU) آپدیت می‌دهد — برای مقیاس B2B شما کاملاً کافی است؛ اگر روزی رشد کرد، پلن پولی آن‌قدرها گران نیست.
2. **امنیت نسخه:** ما از سیاست `appVersion` استفاده می‌کنیم؛ یعنی آپدیت‌های هوایی فقط روی نسخه سازگار اپ سوار می‌شوند — اگر روزی ساختمان را عوض کردی (نسخه جدید APK)، آپدیت‌های قدیمی اشتباهی روی آن نمی‌نشینند. امن است. 🔒
3. **برگشت (Rollback):** اگر آپدیتی اشتباه رفت، می‌شود با `eas update:republish` به قبلی برگشت — نگران نکن، آن لحظه را با هم جلو می‌رویم.
4. OTA روی **`npm run web` اعمال نمی‌شود** — وب همیشه همان باندل تازه سرو می‌شود. OTA فقط برای اپ نصبی (اندروید/iOS) است.
5. اپ‌های نصب‌شده **آفلاین هم باز می‌شوند** — اگر اینترنت نبود، نسخه ذخیره‌شده قبلی اجرا می‌شود و هرگاه اینترنت برگشت، آپدیت گرفته می‌شود.
