# راهنمای تست IDOR ویزیتور (قدم ۲) — نسخه ۱.۱

این تست خودکار اثبات می‌کند که فیکس امنیتی فاز ۵-۱ کار می‌کند:
سفارشی که «ویزیتور ۱» ثبت می‌کند نباید در لیست «ویزیتور ۲» دیده شود.

> ⚠️ اگر نسخه قبلی را در پوشه `idor-test\` اکسترکت کرده بودید، این نسخه مستقیم در
> ریشه استخراج می‌شود و cmd کنار ps1 می‌نشیند → مشکل «File parameter does not exist» حل است.
> (پوشه قدیمی idor-test را می‌توانید حذف کنید.)

## مسیر توصیه‌شده (خودکارِ کامل — با ویزیتورِ واقعی از فایل env)

### ۱) دو خط به .env خودتان اضافه کنید (فقط یک‌بار)
فایل `wholesale-api\.env` را با Notepad باز کنید و این دو خط را آخرش اضافه کنید
(الگوی آماده در `.env.example` هم هست):

```
VISITOR1_PHONE="09123456701"
VISITOR2_PHONE="09123456702"
```

### ۲) ساخت ویزیتورها (پنجره CMD)
```cmd
cd C:\Users\sam\Desktop\workspace-01\wholesale-api
npm run db:seed
```
انتظار: `✅ Visitor user created: ...` (غیرمخرب است؛ دیتای فعلی پاک نمی‌شود)

### ۳) بالا آوردن سرور
```cmd
npm run start:dev
```

### ۴) اجرای تست
دابل‌کلیک روی `run-visitor-idor-test.cmd` (در ریشه workspace-01).
چون نقش‌ها از قبل VISITOR هستند، اسکریپت خودش تشخیص می‌دهد و **بدون هیچ کار دستی** تا انتها می‌رود.

### ۵) نتیجه
خط آخر را برایم بفرستید:
- `*** PASS ***` ✅
- غیر از آن → فایل `idor-test-report.txt` را بفرستید.

## مسیر جایگزین (بدون env/seed — فقط برای حالت CUSTOMER)
مراحل ۱ و ۲ را رد کنید. اسکریپت خودش کاربرها را با نقش عادی می‌سازد و در انتها
«فاز ب» را از شما می‌خواهد (تغییر دستی نقش به VISITOR در Prisma Studio) — اختیاری.

## مواردی که ممکن است وسط کار بخواهد
- **Customer id** (مشتری تاییدشده): `npm run db:studio` → `localhost:5555` → جدول
  Customer → ردیفی با `status = APPROVED` → کپیِ `id` → Paste در اسکریپت.
- **Product id** (کالای فعال با موجودی): جدول Product → `isActive=true` و `stock>0`.

## خطاهای رایج
- `File parameter does not exist` → cmd و ps1 کنار هم نیستند؛ از همین زیپ جدید استفاده کنید.
- `429` → ۶۰ ثانیه صبر و اجرای مجدد.
- `connection refused` → سرور بالا نیست (مرحله ۳).
- برای اجرای مجدد با شماره‌های دیگر: `run-visitor-idor-test.cmd -Phone1 09120000005 -Phone2 09120000006`

یادداشت: تست یک سفارش واقعی با یادداشت `IDOR-TEST` می‌سازد (بعداً از پنل قابل حذف است).
