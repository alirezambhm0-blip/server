
### درس عملی (برای AI بعدی)

> **همیشه `git ls-tree -r` بزنید، نه `git ls-tree`.**
> و برای «آیا فایل X وجود دارد؟» از `git ls-files --error-unmatch <path>` استفاده کنید،
> نه از grep روی خروجی غیربازگشتی.

> همین یک پرچم `-r` باعث شد یک ادعای غلط در **۸ فایل** مستندات پخش شود

## 💎 ۵. یافته‌های تازه‌ای که این سندها به ما دادند

این‌ها را **بدون بازیابی، هرگز نمی‌دانستیم**:

### ۵-۱. ⭐ نام‌گذاری مختلط دیتابیس — مهم‌ترین یافته

`Project_Context.md` §۶ ادعا می‌کند PostgreSQL **نام‌گذاری ناسازگار** دارد. سنجیدم و **درست بود**:

```
جدول‌های با @@map به snake_case ......... ۲۲ (همهٔ جدول‌ها)
فیلدهای با @map به snake_case ........... ۱۸ فقط
```

یعنی **جدول‌ها snake_case هستند ولی اکثر ستون‌ها CamelCase**. خود schema هم این را مستند کرده:

```prisma
// wholesale-api/prisma/schema.prisma
nameNormalized String?   @map("name_normalized") // فقط این snake_case است
orderNumber    String    @unique @map("order_number") // snake_case (تایید شده)
subtotalAmount Int       @map("subtotal_amount")      // snake_case (تایید شده)

isActive   Boolean  @default(true)   // ← بدون @map = ستون واقعاً "isActive" است
createdAt  DateTime @default(now())  // ← بدون @map = ستون واقعاً "createdAt" است
```

> **⚠️ قاعدهٔ حیاتی:** اگر ستونی `@map` ندارد، **نباید** برایش `@map` اضافه کنید —
> باعث خطای `P2022 (column does not exist)` می‌شود. این دقیقاً چیزی است که
> `Project_Context.md` هشدار می‌دهد و **با کد مطابقت دارد.**
> → به `19-CHANGE-IMPACT-MAP.md` اضافه شد.
